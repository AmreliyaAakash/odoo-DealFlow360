UI System

Every screen in the workspace is built from one small set of primitives, three workspace accents, and two motion mechanisms. This is what they are and how to use them — so the next page you add matches the ones already there.

Scripts

npm run dev          # next dev
npm run typecheck    # tsc --noEmit — touches no build output
npm run build:check  # builds into .next-build, safe while dev is running
npm run lint         # eslint
npm run db:build     # regenerates db/setup.sql from schema + seed + demo

Never run next build while next dev is up. They share .next, and the build corrupts the dev server's route manifest — which shows up as 404s on routes that plainly exist.

Use npm run build:check, which writes to .next-build instead.

Primitives

components/dashboard/panel.tsx is the whole design system. Nine exports. Change them and every screen changes together.

ExportUse for
PanelAny bordered block. Takes delay in ms for entrance stagger.
PanelHeaderIcon + title + caption, optional corner ↗ link, children land as right-side actions.
PageHeaderPage title + caption + badge. Every page owns its own — there is no top bar.
NoticeInline warning (tone="warning") or error (tone="danger").
DataTableScroll container + <table>. Pass head and a minWidth.
Th / Td / TrCells. Tr carries the hover and top border.
EmptyRowThe empty state, spanning colSpan.
StatusBadgeQuotation status pill, tinted from the shared palette.
DiscountBadgeDiscount depth — green under 25%, red over.

The one class string that defines a surface

df-rise-in rounded-xl bg-card p-4 ring-1 ring-foreground/10

A hairline ring rather than a border, so it never adds to layout size; rounded-xl; a flat bg-card with no shadow. Depth comes from the grey page ground (bg-muted/40 on the dashboard layout), not from elevation.

Page skeleton

<main className="flex min-w-0 flex-1 flex-col gap-4">
  <PageHeader title="…" caption="…" badge="…" />
  {error ? <Notice>{error}</Notice> : null}

  <StatCards … />                        // summary first

  <div className="grid gap-4 xl:grid-cols-3">
    <div className="xl:col-span-2">…</div>  // wide: the chart
    <SidePanel … />                        // narrow: the list
  </div>

  <QueueTable … />                       // detail last
</main>

min-w-0 is not optional — without it a wide table blows the flex row out and the page scrolls sideways. Spacing is always gap on the parent, never margins on children.

Defined as WORKSPACES in app/(dashboard)/dashboard-sidebar.tsx. Each entry holds its nav array, home route, CTA copy and three accent class strings. 

finance: {
  nav: FINANCE_NAV,
  home: "/finance",

  button: "bg-emerald-500 hover:bg-emerald-400",

Write accent classes as whole strings. Tailwind scans source text — `bg-${hue}-500` produces nothing at build time. That is why these are spelled out rather than composed.

Admins use the manager workspace and additionally get the Backend link. Nav visibility mirrors the gating in proxy.ts, so nobody sees a link that would bounce them.

How a badge is tinted

Hex plus alpha suffix, inline — not a Tailwind class — because the value comes from data at runtime: 

style={{ background: `${color}1f`, color }}   // 1f ≈ 12% alpha

pending approval   approved   won

Semantic colour is separate from accent

Green/amber/red mean good, watch, bad everywhere, independent of which workspace you are in. Risk bands come from RISK_BANDS in lib/business-logic.ts — amber at 40, red at 70:

26low — 12% off, 22% margin
64medium — 30% off, 10% margin
100high — 41% off, 4% margin, ₹1.2Cr

The score itself is a weighted blend: discount depth 45%, margin erosion 35%, deal size 20%.

Motion

Two mechanisms, chosen by whether the movement happens once on load or responds to the user. Both respect prefers-reduced-motion.

A. CSS stagger — entrances

For anything that just needs to arrive: panels, table rows, list items. Defined once in app/globals.css, driven by an inline --df-delay custom property so each sibling can offset itself. 

@keyframes df-rise-in {
  from { opacity: 0; transform: translateY(8px); }
  to   { opacity: 1; transform: none; }
}

.df-rise-in {
  animation: df-rise-in 420ms cubic-bezier(0.22, 1, 0.36, 1) both;
  animation-delay: var(--df-delay, 0ms);
}
<Tr className="df-rise-in"
    style={{ "--df-delay": `${index * 40}ms` } as React.CSSProperties}>

B. Framer Motion — interaction

Reach for it when CSS cannot express the movement. Six files use it, and each has a reason:

WhereWhy not CSS
manager/stat-cardsLooping badge pulse, gated on count > 0
manager/anomaly-highlightsDot fades in, then loops only when drift is severe
manager/pending-approvals-tableheight: 0 → auto on expand, via AnimatePresence
finance/queue-tabsTab crossfade with mode="wait"
finance/warehouse-stockBar width grows from 0 to its share
finance/stat-cardsEntrance, consistent with its manager twin
 
// The pulse only runs when there is something to act on.
const pulsing = Boolean(tile.pulse) && tile.value > 0 && !reduceMotion;

<motion.span
  animate={pulsing ? { scale: [1, 1.05, 1] } : { scale: 1 }}
  transition={pulsing
    ? { duration: 1.8, repeat: Infinity, ease: "easeInOut" }
    : { duration: 0.2 }}
/>

Always call useReducedMotion() in a Framer Motion component and branch on it. The CSS media query in globals.css covers the stagger classes, but it does not reach JS-driven animation.

C. Count-up

lib/use-count-up.ts animates a stat from 0 on mount — requestAnimationFrame with easeOutCubic. Every state update happens inside the frame callback, never in the effect body, so mounting does not cascade a render.

Charts

Recharts, with the same five conventions in every file.

ChartTypeLives in
Quotation PipelineDual-axis linerep/pipeline-chart
Value by CategoryHorizontal barrep/category-mix-card
Pipeline by StatusDonutrep/status-mix-card
Approval volumeStacked barmanager/approval-volume-chart
MRR trendGradient areafinance/mrr-chart

The five conventions:

  1. Wrap in ResponsiveContainer inside a fixed-height div (h-60).
  2. Axes: tickLine={false} axisLine={false} fontSize={11}, colour from stroke="currentColor" + className="text-muted-foreground" so they follow the theme.
  3. Grid: strokeDasharray="3 3", horizontal only.
  4. Tooltip contentStyle reads var(--popover) and var(--border) — never hardcoded colours.
  5. Money on an axis goes through formatCompactCurrency, so ticks read ₹7.1L and ₹1.2Cr.

Counts and money never share an axis. They differ by orders of magnitude — put each on its own yAxisId, or the smaller series flatlines against the larger scale.

Recharts' Tooltip formatter is typed as ValueType | undefined. Let TypeScript infer the parameter and coerce inside — Number(value ?? 0) — rather than annotating it number, which will not compile.

Numbers & money

All formatting goes through lib/quotations.ts. Nothing calls Intl directly.

HelperInputOutput
formatCurrency714000₹7,14,000
formatCurrency12345678₹1,23,45,678
formatCompactCurrency714000₹7.1L
formatCompactCurrency12345678₹1.2Cr
formatNumber123456712,34,567
formatPercent0.15315.3%

The locale is en-IN, not just the INR symbol. That is what produces lakh/crore grouping — ₹1,23,45,678 rather than ₹12,345,678. Decimals are dropped on display; tables read better without paise.

Any column of digits gets tabular-nums so the figures line up down the column.

File map

Where the UI lives. Route groups in parentheses do not appear in URLs.

app/(dashboard)/layout.tsx shell: sidebar + content, no top bar app/(dashboard)/dashboard-sidebar.tsx WORKSPACES — nav + accent per role app/(dashboard)/rep/ indigo · dashboard, upsell app/(dashboard)/manager/ amber · dashboard, team pipeline app/(dashboard)/finance/ emerald · dashboard, fulfillment, billing, warehouses app/(dashboard)/quotations/ list + [id] builder app/(dashboard)/backend/ admin config, four CRUD screens components/dashboard/panel.tsx the primitives components/dashboard/status-badge.tsx StatusBadge, DiscountBadge components/ui/ base-ui / shadcn leftovers — Dialog only lib/status.ts STATUS_COLORS, statusLabel lib/quotations.ts pricing + all money formatting lib/business-logic.ts risk, approvals, proration, deal health lib/use-count-up.ts stat animation app/globals.css theme tokens + df-rise-in / df-check-in

Each dashboard folder follows the same shape: page.tsx (server, guards + loads), data.ts (queries + aggregation), types.ts (view models and shared constants), then one client component per panel.

Shared constants belong in types.ts, not data.ts. A client component importing from data.ts drags clerkClient into the browser bundle and the build fails. That is why ANOMALY_DELTA_PCT sits in types.ts.

House rules

The things that will bite you if you skip them.

RuleBecause
Server Component by defaultAdd "use client" only for state, motion or event handlers.
Icons from /dist/ssr in Server ComponentsThe regular entry point is client-only.
min-w-0 on flex childrenOtherwise wide tables force horizontal page scroll.
gap, not marginsMargins collapse and double unpredictably between siblings.
Wide content gets overflow-x: autoThe container scrolls, never the page body.
No setState in an effect bodyThe React compiler lint rejects it — use a rAF or event callback.
Theme colours via tokensbg-card, text-muted-foreground — never a literal that only works in one theme.
Empty states are designedEvery table has an EmptyRow; every panel has a "nothing here" line.
Errors render, never throwData loaders return loadError; the page shows a Notice and still draws.

Adding a page — the short version

  1. Create app/(dashboard)/<area>/page.tsx as a Server Component.
  2. Guard it — currentUser() from lib/auth.ts, redirect on the wrong role.
  3. Put queries in a sibling data.ts returning { …, loadError }.
  4. Compose the body from PageHeader → stat tiles → chart/side grid → table.
  5. Add the route to the right *_NAV array, and to proxy.ts if it needs gating.
  6. npm run typecheck && npm run build:check.
